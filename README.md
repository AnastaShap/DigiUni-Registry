# DigiUni-Registry
DigiUni-Registry — це сучасна консольна інформаційна система для автоматизації обліку структури університету (НаУКМА). Проєкт охоплює ключові теми курсу Advanced Java: ООП, Java Stream API, власні анотації, Reflection API, бітові маски для прав доступу, обробку винятків та роботу з файловою системою, багатопоточність.

**Основні завдання**
реалізувати предметну область: Faculty, Department, Student, Teacher;
додати авторизацію та рольову модель USER / MANAGER / ADMIN;
реалізувати збереження та завантаження даних у файл;
описати структуру застосунку за допомогою UML-діаграм.

## Розподіл задач
Учасник та Основні завдання
- Шаповал Анастасія: Бізнес-логіка роботи з даними, сервіси, частина пошуку та операцій зі студентами й кафедрами.
- Шкаровська Анастасія: Консольне меню, авторизація, рольова модель, збереження/завантаження даних, підготовка UML та звіту.

## Архітектура системи та UML-діаграми
У звіті наведено UML-діаграми: 
- Class diagram та component / data flow diagram. Вони відображають вимоги до ролей, предметної області та загальної архітектури системи.
- Component / Data Flow Diagram - Компонентна схема показує, як консольне меню взаємодіє з сервісами, авторизацією, репозиторіями та модулем збереження даних
- Є також загальні UML-діаграми повного проєкту.
**Class Diagram**
Базовим класом системи є *Person*, який містить спільні поля (ID, ПІБ, контакти).
- **Student**: Розширює Person, додаючи специфічні поля: номер студентського квитка, курс (1-6), група, рік вступу, форма навчання та статус.
- **Teacher**: Містить дані про посаду, науковий ступінь, стаж та навантаження.
- **Faculty & Department**: Організовують ієрархічну структуру. Студент жорстко прив’язаний до кафедри, яка, у свою чергу, належить факультету

## Рольова модель доступу (RBAC)
У системі реалізовано три рівні доступу для забезпечення безпеки даних:
Роль,             Доступ,                     Опис
USER,"Перегляд, пошук, звіти",Не має права виконувати CRUD-операції.
MANAGER,"CRUD для студентів, факультетів, кафедр",Повний доступ до даних університету без керування користувачами.
ADMIN,Усі права MANAGER + керування користувачами,"Створення користувачів, зміна ролей, блокування/розблокування."

## Архітектура системи
Наш поєкт побудований за принципом розділення відповідальності (Separation of Concerns):
1. UI Layer: Консольні меню для зручної взаємодії з користувачем.
2. Service Layer: Класи бізнес-логіки (StudentService, DepartmentService тощо), що виконують основні операції.
3. Repository Layer: Репозиторії для збереження даних у пам'яті під час виконання програми.
4. IO Layer: Сервіси серіалізації для довготривалого зберігання даних у форматі .bi

## Структура проекту
Проєкт організований як стандартний **Maven проект**:
- src/main/java — вихідний код системи.
- src/test/java — юніт-тести для перевірки логіки сервісів та доступу.
- data/ — каталог для збереження бінарних snapshot-файлів.
- logs/ — лог-файли роботи системи.
